# Part A — Jun-6 V: Juno-Style Oscillator & Filter Spec

29 Oct 2026 · @Arent Todal

Reverse-engineered from libjunoProcessor.dylib (arm64, 1.9 MB) and configuration XMLs in Arturia Jun-6 V v1.6.6. Models three Roland Juno variants: Juno-6, Juno-60, and Juno-106.

## 1. Architecture Overview

The Roland Juno series (Juno-6, Juno-60, Juno-106) are single-oscillator-per-voice polysynths. Unlike the Prophet-5 with its two full VCOs per voice, the Juno uses one DCO (Digitally Controlled Oscillator) — a hybrid design where the pitch is digitally locked but the waveform is generated by analog waveshapers. This gives perfect tuning stability with analog warmth.

### Three hardware variants

Arturia's HPFMode parameter selects between three models:

| Mode | Synth | Year | Key differences |
|---|---|---|---|
| 6 | Juno-6 | 1982 | Stepped HPF (4 positions), unfiltered noise, wider component tolerances |
| 60 | Juno-60 | 1982 | Same as Juno-6 but with patch memory; filtered noise (Juno60NoiseLPF) |
| 106 | Juno-106 | 1984 | Continuous HPF, different filter chip (80017), slightly different character |

The DiscreteCutoff parameter (4 positions: 0–3) reflects the Juno-6/60's physical 4-position HPF switch. In Juno-106 mode, the HPF cutoff is continuous.

### Voice structure

Up to 36 polyphonic voices, each containing:
- JunoDCO — single oscillator with saw, square (variable PW), and sub-oscillator
- JunoVCF — 4-pole (24 dB/oct) OTA lowpass filter modeled on the Roland IR3109
- JunoHPF — high-pass filter (stepped or continuous depending on mode)
- JunoVCA — voltage-controlled amplifier with envelope or gate mode
- JunoADSR — two ADSR envelopes (Env1 for VCF+VCA, Env2 for modulation matrix)
- JunoLFO — LFO with delay/rise fade-in
- Juno6Chorus — the iconic BBD chorus (shared across all voices)

### Signal flow per voice

```
DCO Saw ──────┐
DCO Square ───┤
DCO Sub ──────┼──► Mixer ──► HPF ──► VCF (4-pole OTA LP) ──► VCA ──► Chorus ──► Output
Noise ────────┘                          ▲                     ▲
                                   Env1 + LFO + KBD       Env1 or Gate

LFO ──► DCO Pitch, DCO PWM, VCF Cutoff
Env1 ──► VCF Cutoff (bipolar), VCA Level
```

## 2. DCO Oscillator (JunoDCO)

The Juno's DCO is conceptually different from a free-running VCO. In the original hardware, a master clock divider provides a digitally precise pitch reference, while analog waveshapers create the actual waveforms. This gives the Juno its characteristic "perfectly in tune but still analog" sound.

### 2.1 Waveform generation

Arturia uses the same PolyBLEP framework as their other synths (PolyBlepSawBase, PolyBlepSquareBase, PolyBlepPhaseGenBase) — all with the `<true>` template parameter enabling post-filtering.

Sawtooth (SawOn):

```
saw = 2.0 × phase - 1.0 - polyblep(phase, dt)
```

Standard PolyBLEP saw with residual correction at the reset discontinuity.

Square / Pulse (SquareOn): variable pulse width controlled by the PWM system:

```
pulse = (phase < pulseWidth) ? 1.0 : -1.0
pulse -= polyblep(phase, dt)
pulse += polyblep(fmod(phase + 1.0 - pulseWidth, 1.0), dt)
```

Sub-oscillator (SubOn, SubVol): a square wave one octave below the main oscillator, generated by dividing the main phase by 2:

```
sub = (phase_divided_by_2 < 0.5) ? 1.0 : -1.0
```

The SubVppAmt (peak-to-peak voltage amount) parameter controls the sub-oscillator's amplitude scaling — modeling the voltage swing variation in the original analog divider circuit. The SubDispOn flag enables per-voice dispersion of this amplitude.

Noise (NoiseVol): white noise generator mixed in at the DCO stage. The Juno60NoiseLPF switch toggles a lowpass filter on the noise — the Juno-60 had slightly filtered noise compared to the Juno-6's raw white noise.

### 2.2 Pulse Width Modulation (PWM)

The PWMMode parameter selects the modulation source:

| Mode | Source | Behavior |
|---|---|---|
| Envelope | Env1 output | PW sweeps with the filter envelope — characteristic Juno string sound |
| Manual | PWMManual knob | Static pulse width (0 = thin, 0.5 = square) |
| LFO | LFO1 output | Cyclic PW sweep — the classic Juno chorus-like PWM pad |

The DCOPWMAmount parameter scales the modulation depth. PWM range is typically 5%–95% to prevent the pulse from disappearing completely.

### 2.3 DCO pitch drift modeling

The DCODrift parameter (0–1) adds slow random pitch variation to simulate analog oscillator instability:

```
pitch_offset = driftAmount × lowpass_noise(seed)    // very slow random walk
final_pitch = base_pitch × 2^(pitch_offset / 12)
```

The original Juno DCO was inherently stable (digital pitch control), but there was still slight drift from the analog waveshaper circuits and temperature sensitivity. The PitchDriftST (semitone) parameter controls the maximum drift range.

### 2.4 Post-filter (PolyBlepPostFilter)

As with the Prophet-5 V, a gentle lowpass filter after waveform generation removes residual aliasing energy above Nyquist that the 2-point PolyBLEP didn't fully suppress.

### 2.5 Mixer

The four sources are mixed before entering the filter chain:

```
mixed = saw × sawOn + pulse × squareOn + sub × subOn × subVol + noise × noiseVol
```

Each waveform is switched on/off independently (not blended), matching the original hardware's physical toggle switches. Volume control is only available for the sub-oscillator and noise.

## 3. VCF Filter (JunoVCF)

The Juno filter is a 4-pole (24 dB/oct) OTA lowpass based on the Roland IR3109 chip — a quad OTA (Operational Transconductance Amplifier) designed specifically for synthesizer filters. This is fundamentally different from the transistor ladder used in the Prophet-5.

### 3.1 OTA filter topology

The IR3109 contains four matched OTA stages, each acting as a voltage-controlled current source that drives a grounded capacitor:

```
input ──► OTA1 ──► C1 ──► OTA2 ──► C2 ──► OTA3 ──► C3 ──► OTA4 ──► C4 ──► output
                                                                         │
                                                        resonance ◄─────┘
```

Each OTA stage has the transfer function:

I_out = I_bias · tanh(V_in / (2 V_T))

where V_T ≈ 26 mV is the thermal voltage. For the digital model, the key insight is that solving for voltage involves the inverse hyperbolic sine (asinh), which is why the binary imports asinhf rather than tanhf.

### 3.2 Digital implementation

The filter is implemented as a TPT (Topology-Preserving Transform) OTA ladder. For each 1-pole stage:

```
// OTA integrator with nonlinear transfer
v_in = input_to_stage - stage_state
g = cutoff_coefficient    // g = tan(π × fc / fs) or similar

// Nonlinear OTA response
stage_state += g × asinh_approx(v_in × drive)
output = stage_state
```

The asinh appears because the OTA's tanh transfer, when inverted for the feedback path, becomes asinh. This gives the IR3109 its characteristic soft saturation that's different from a transistor ladder — smoother, less aggressive, with a rounder resonance peak.

### 3.3 Cutoff frequency mapping

From the XML: mapping="Exp(10.26)", range 0.2991 Hz to 102,600 Hz.

This extremely wide range extends well above Nyquist — the filter coefficient is clamped internally. The mapping:

```
cutoff_hz = 0.2991 × (102600 / 0.2991) ^ knobPosition
```

The oversampling via LRS functions (lrsSrcUp, lrsSrcUD) pushes the internal sample rate higher to allow the filter to operate accurately at high cutoff frequencies without aliasing from the nonlinear asinh saturation.

### 3.4 Resonance and self-oscillation

The Res parameter (0–1, linear mapping) controls the feedback gain. The IR3109's resonance has a distinctive quality:
- At low resonance: subtle emphasis at the cutoff frequency
- At moderate resonance: a warm, singing peak that doesn't thin out the bass as aggressively as a transistor ladder
- At maximum: clean self-oscillation producing a near-sine wave

The ResNoiseAmt parameter (0–2) adds noise into the resonance feedback path, modeling the thermal noise of the analog feedback resistor:

```
feedback = resonance × output + resNoiseAmt × noise_sample
```

This noise prevents the self-oscillation from being perfectly clean (as it would be in a naive digital model) and adds the subtle grit that makes analog filters sound alive.

### 3.5 Cutoff modulation

The final cutoff frequency combines multiple modulation sources:

```
cutoff_total = cutoff_base
    × 2^(envAmt × envPolarity × env1_output × range)     // envelope (bipolar!)
    × 2^(lfoAmt × lfo_output × range)                     // LFO modulation
    × 2^(keyAmt × (note - 60) / 12 × range)              // keyboard tracking
    × 2^(dispersion_cutoff × cutDispAmt)                   // per-voice drift
```

The bipolar envelope (EnvPol: Positive/Negative) is a key Juno feature — negative polarity inverts the envelope, creating filter sweeps that close on attack rather than opening. This is essential for the Juno's characteristic "backwards" pad sounds.

### 3.6 Oversampling

The LRS (Linear Rate-conversion System) functions handle internal oversampling:
- lrsSrcUp — upsample input
- lrsSrcUD — downsample output
- lrsLpFilter — anti-aliasing lowpass
- lrsFilterUp / lrsFilterUD — combined filter + rate conversion

Oversampling is critical because the asinh nonlinearity generates harmonics that would alias without it. The filter likely runs at 2× or 4× the host sample rate internally.

## 4. HPF and Chorus

### 4.1 High-pass filter (JunoHPF)

The HPF sits between the mixer and the VCF. On the original Juno-6/60, this was a simple 1-pole (6 dB/oct) highpass with a 4-position rotary switch.

From the XML: HPF Cutoff range is 17.6 Hz to 2708 Hz (linear mapping).

The DiscreteCutoff parameter has 4 positions (0–3), matching the original hardware switch:

| Position | Approximate cutoff | Effect |
|---|---|---|
| 0 | Off (~17.6 Hz) | Full bass, no HPF |
| 1 | ~130 Hz | Slight bass cut — thins pads |
| 2 | ~500 Hz | Moderate cut — removes body |
| 3 | ~2700 Hz | Aggressive cut — nasal, thin |

In Juno-106 mode (HPFMode = 106), the cutoff becomes continuously variable instead of stepped.

The HPF is a standard 1-pole highpass:

```
// 1-pole highpass
y[n] = α × (y[n-1] + x[n] - x[n-1])
// where α = 1 / (1 + 2π × fc / sampleRate)
```

The HPF is critical to the Juno sound — position 1 or 2 on pads removes the low-end mud and gives the characteristic thin, shimmery quality that sits perfectly in a mix.

### 4.2 Juno-6 Chorus (Juno6Chorus / ChorusJun6)

The Juno chorus is arguably the most iconic part of the synth's sound. It uses a BBD (Bucket Brigade Device) delay line with a slow LFO modulation — a simple concept that produces a lush, wide stereo effect.

Chorus modes (from ChorusModes):

| Mode | LFO Rate | Delay Depth | Character |
|---|---|---|---|
| Off | — | — | Dry mono output |
| Mode 1 | ~0.5 Hz | Shallow | Subtle shimmer, gentle width |
| Mode 2 | ~0.8 Hz | Deep | Thicker, more obvious modulation |
| Mode 1+2 | Both | Both | Maximum lushness, the classic Juno pad sound |

How it works: the chorus creates a stereo signal from the mono synth voice by splitting it into two paths, each passing through a BBD delay modulated by a triangle LFO:

```
// Two delay taps modulated by inverted LFOs
delay_L = base_delay + depth × lfo_triangle(rate, phase=0°)
delay_R = base_delay + depth × lfo_triangle(rate, phase=180°)

output_L = input + delayed_signal(delay_L)
output_R = input + delayed_signal(delay_R)
```

In Mode 1+2, two separate modulation rates run simultaneously, creating a more complex and less periodic movement.

The ChorusNoiseOn parameter enables noise injection into the delay line, modeling the clock feedthrough noise inherent in real BBD chips. This adds a subtle gritty texture — the reason the original Juno chorus sounds "warm" rather than pristine. With ChorusNoiseOn = Off, the chorus is cleaner (useful for modern production).

BBD delay modeling: a real BBD is a series of capacitor stages that pass the signal along like a bucket brigade. Each stage introduces:
- Slight signal degradation (noise, distortion)
- Bandwidth limiting (the BBD acts as a lowpass at high clock rates)
- Clock feedthrough noise

The Juno6Chorus class likely models these imperfections with a lowpass-filtered delay line and injected noise, rather than simulating individual BBD stages.

## 5. Envelopes, LFO, and Modulation

### 5.1 JunoADSR envelope

Two envelopes per voice: Env1 (VCF/VCA) and Env2 (modulation matrix only, Arturia addition).

Env1 time ranges (from XML):

| Stage | Mapping | Min | Max |
|---|---|---|---|
| Attack | Exp(5.025) | 0.8 ms | 2.975 s |
| Decay | Exp(4.601) | 1.6 ms | 18.96 s |
| Sustain | Linear | 0.0 | 1.0 |
| Release | Exp(5.097) | 2 ms | 16.98 s |

Env2 has identical time ranges.

The original Juno-6 had a simplified envelope on its VCA — just a gate mode (instant on/off) or the full ADSR. The JunoVCA_EnvMode parameter preserves this:

| Mode | Behavior |
|---|---|
| Env | VCA follows Env1 ADSR |
| Gate | VCA is fully on when key is held, instant off on release |
| Env2 | VCA follows Env2 (Arturia addition) |

Gate mode is essential for organ-like sounds and the classic Juno brass stab.

### 5.2 JunoLFO

The LFO provides triangle-wave modulation routed to DCO pitch, DCO pulse width, and VCF cutoff (each with independent amount controls on the panel).

Rate: Exp(3.1062), range 0.038–21.5 Hz (free-running) or synced to tempo.

Delay/Rise: the original Juno-6 had a manual LFO delay — pressing a key triggers a fade-in of the LFO modulation. The ModeSw parameter selects:

| Mode | Behavior |
|---|---|
| Delay + Rise | LFO starts at zero, delays, then fades in |
| Rise | LFO starts at zero and immediately fades in |

Delay time: Exp(3.56), range 5 ms to 3.08 s. Rise time: Exp(3.254), range 7 ms to 2.89 s.

This is how the Juno creates delayed vibrato — hold a note and the pitch modulation gradually fades in, mimicking a string player's technique.

### 5.3 Modulation routing

The original Juno had fixed modulation routing. Arturia adds an extended modulation matrix.

Original Juno routing (hardwired):
- LFO → DCO Pitch (amount: DCOLFOAmount)
- LFO → DCO PWM (when PWMMode = LFO)
- LFO → VCF Cutoff (amount: JunoVCF_LFOAmt)
- Env1 → VCF Cutoff (amount: JunoVCF_EnvAmt, polarity: EnvPol)
- Env1 → DCO PWM (when PWMMode = Envelope)
- Env1 or Gate → VCA Level
- Keyboard → VCF Cutoff (amount: JunoVCF_KeyAmt)

Extended matrix (Arturia additions):
- 6 mod sources: Env2, LFO2, ModWheel, Velocity, AfterTouch, MPE Slide
- 35 destinations including DCO Pitch, PWM, Sub Vol, Noise Vol, VCF parameters, HPF, both envelopes, both LFOs, arpeggiator, portamento, delay, and reverb
- 1 audio-rate source (Env2) routable to VCA Level for AM effects

## 6. Analog Modeling: Seed-Based Dispersion

Unlike the Prophet-5 V which uses pre-computed dispersion tables, the Jun-6 V uses a seed-based random generation system — each dispersion parameter has a seed value (0–99) that deterministically generates per-voice offsets.

### 6.1 Dispersion seeds

From the XML, 8 seed parameters control all per-voice variation:

| Seed | Default | Controls |
|---|---|---|
| JunoDCO_DispersionSeed1 | 31 | DCO pitch variation |
| JunoDCO_DispersionSeed2 | 39 | DCO square wave shape |
| JunoDCO_DispersionSeed3 | 35 | DCO saw wave shape |
| JunoDCO_DispersionSeed4 | 29 | DCO sub-oscillator amplitude |
| JunoDCO_DispersionSeed5 | 6 | DCO pulse width offset |
| JunoVCF_DispersionSeed1 | 27 | VCF cutoff offset |
| JunoVCF_DispersionSeed2 | 25 | VCF resonance offset |
| Env1_DispersionSeed1 | 32 | Envelope time variation |

Changing a seed regenerates a completely different set of per-voice offsets for that parameter. This allows users to "re-roll" the analog character without changing the dispersion amount.

### 6.2 Dispersion toggles and amounts

Each dispersed component has an independent on/off switch and amount control:

| Component | Toggle | Amount | Range |
|---|---|---|---|
| DCO Square shape | SquareDispOn | (fixed) | On/Off |
| DCO Saw shape | SawDispOn | (fixed) | On/Off |
| DCO Sub amplitude | SubDispOn | SubVppAmt | 0–5 |
| DCO Pulse width | PWDispOn | PWDispAmt | 0–5 |
| DCO Pitch | PitchStDispOn | PitchStDispAmt | 0–1, Exp(2) |
| VCF Cutoff | CutDispOn | CutDispAmt | 0–5 |
| VCF Resonance | ResoDispOn | ResoDispAmt | 0–5 |

The dispersion amounts have a wide range (0–5) on the filter and oscillator shape parameters, allowing exaggerated analog character when desired.

### 6.3 What dispersion models

Pitch dispersion (PitchStDispAmt, exposed as "Voice Detune" in the UI with Exp(2) mapping): each voice's DCO runs at a slightly different pitch. On the real Juno, this came from component tolerances in the pitch CV-to-frequency converter. Even though the DCO's pitch was digitally controlled, the analog waveshaper's timing had slight per-voice variation.

Square/Saw/Sub shape dispersion: the analog waveshaper circuits (comparators for square, integrator reset for saw, flip-flop for sub) had component tolerances that made each voice's waveform subtly different — slightly rounded edges, asymmetric duty cycles, different rise/fall times.

Filter cutoff and resonance dispersion: the most sonically significant. Each voice's IR3109 OTA chip had different bias current matching, meaning the cutoff frequency and resonance peak varied. This is why playing a chord on a real Juno sounds lush — each note passes through a slightly different filter.

### 6.4 DCO drift vs dispersion

Two separate systems model analog instability:
- Dispersion (seeds + amounts) = static per-voice offsets that remain constant for the life of a note. These model manufacturing tolerances.
- DCO Drift (DCODrift, 0–1) = slow, time-varying random pitch modulation that models thermal drift and power supply fluctuation. This changes continuously, even on held notes.

Both combine: final_pitch = base_pitch + dispersion_offset + drift_offset

## 0. READ THIS FIRST: MANDATE AND NON-NEGOTIABLES

### 0.1 Product objective

Add a real Juno-style sound-generation personality to ANDOR Analog while preserving the current synthesizer as-is. The musician can select, independently:
1. OSC 1 model — Classic VCO / Juno DCO / Wide VCO (Wide if implemented by the separate V3 Organic Morph plan; do not manufacture a nonworking model).
2. OSC 2 model — independently Classic VCO / Juno DCO / Wide VCO.
3. FILTER model — current four-pole Analog Ladder / new Juno-style OTA four-pole lowpass.
4. Juno family variant — 6 / 60 / 106: calibration personality applied only to active Juno-mode components, never a replacement of the entire instrument.
5. HPF — the variant's characteristic static four-position pre-VCF high-pass / bass-emphasis option.
6. Chorus — dedicated shared stereo chorus character (OFF / I / II / I+II creative mode). Not per-oscillator.
7. Musical articulation — Juno-style ENV/GATE VCA option, bipolar VCF envelope (the existing filter ENV depth is already signed), LFO delay + rise, ENV/MAN/LFO PWM options, subtle per-voice tolerances.

Allow hybrid combinations such as Classic VCO + Juno DCO into Juno OTA and, once the separate organic expansion is implemented, analog + OSP organic source into Juno OTA.

## 4. JUNO DCO DSP: EXACT DESIGN

### 4.1 DCO source definition

A Juno DCO is a compound source, not three extra visible oscillator cards:

```
Digital-rate pitch/phase reference
     ├─ band-limited rising saw  (switch on/off)
     ├─ band-limited pulse/square (switch on/off, variable duty cycle)
     └─ divider sub-square       (switch on/off, level, octave -1 initially)
                    └─ sum / calibration / output gain
```

White noise continues to come from the existing voice noise path analog.noise with optional Juno variant-specific coloration. If both OSC 1 and OSC 2 are in Juno mode, this does not duplicate the global noise source. Preserve that existing noise automation behavior.

Noise-color implementation contract: the uploaded reference explicitly distinguishes Juno-6 raw white noise from Juno-60 low-pass-colored noise (Juno60NoiseLPF). Implement one seeded shared noise source with NoiseColor selected by analog.juno.variant only when Juno character is active, so the 6 preset routes raw whitened noise and the 60 applies a first-order lowpass or a measured calibrated filter. The source does not establish the exact 60 filter cutoff; choose an initial 7 kHz host-independent frequency then calibrate by listening. For 106 use a documented neutral/filtered choice according to public evidence and listening, not an invented official circuit claim. Apply this filter to noise before the DCO/HPF mixer and do not alter existing Classic+Ladder noise color. Prepare/reset its state per voice; changes of variant must fade without clicks. No extra host parameter is required in V1, though an advanced analog.juno.noiseColorOverride may be appended in a future release.

When OSC 2's existing analog.osc2.lowFreq control is enabled and OSC 2 is a Juno DCO used as a modulation oscillator, keep the main DCO cycle tracking stable but mute or explicitly gate its sub divider by default at infrasonic frequencies; do not emit quasi-DC into the audio path. This gating is a mode-specific decision and must leave OSC 2's audible mode unchanged.

### 4.3 Core frequency and phase

Host MIDI pitch follows existing Synth::updateVoiceControl pitch pipeline. For each internal sample:

```
noteSemitones = midiNote + existingOctave/coarse/fine + pitchBend + LFO_pitch
               + modeSpecificStaticDispersion + slowDrift
fHz = 440 * 2 ^ ((noteSemitones - 69)/12)
phaseInc = clamp(fHz / internalSampleRate, 1e-9, 0.45)
phase = fractional(phase + phaseInc)
```

Maintain the current double-precision oscillator phases and timing. Juno DCO must not inherit the full VCO free-running pitch instability automatically: static calibration and very slow drift are deliberately much smaller than Classic VCO. Pitch changes must preserve phase continuity except when existing analog.phase is explicitly RESET.

### 4.4 Saw and pulse

For a rising saw, naiveSaw = 2*p - 1 and correct the wrap using the existing B-spline residual. For pulse with width w, naivePulse = (p < w ? +1 : -1) - (2*w-1) with corrections at the falling-width edge and rising-wrap edge. Maintain the current phase/correction sign conventions; regression against numerical bandlimited reference.

Independent switches: Saw and Pulse are independently ON/OFF. Possible states: none, saw only, pulse only, saw+pulse. When neither is enabled but sub is enabled, sub still plays. When all off, DCO is silent except shared noise; do not invent a default sine.

Amplitude: sum components with calibrated gains, not blind 1/sqrt(N) when the goal is vintage mixer behavior. Start with sawGain=0.65, pulseGain=0.65, subGain=0.65*subLevel at 0 dB component calibration, then optimize to avoid large level jumps when two switches turn on. These are engineering starting values, not hardware measurements. Preserve separate existing osc1.level/osc2.level gain after the DCO module.

### 4.5 Sub oscillator and divider precision

A true octave-down square needs a two-cycle period of the main DCO. subPhase = (phase + (cycleCount & 1)) * 0.5 produces a half-rate phase if cycle parity tracks every main wrap accurately; an independent subPhase += phaseInc*0.5 is also valid if aligned to main phase and pitch/sync transitions are handled carefully.

Required antialiasing: both sub wrap and sub 50% edge must be BLEP-corrected. A naive sign flip at main wrap produces easily measurable aliasing and clicks. Main osc::walk may detect wraps at fractional sample positions; propagate those times to the sub divider and apply the correction in subCorrection using the same fractional-edge timing.

The divider must behave under DCO pitch modulation, free-running phase, voice stealing and analog.sync. Contract: sync resets only the selected slave oscillator's main phase; define whether its sub divider also resets. Initial choice: sub follows the main reset, crossfade if it creates transient artifacts; document as an intentional creative behavior rather than a literal hardware claim.

## 5. JUNO OTA FOUR-POLE VCF: ALGORITHM, STABILITY AND TEST CONTRACT

### 5.1 The audible distinction we want

An OTA-based Juno-style filter must have a distinctive combination of:
- four-pole lowpass slope (nominal 24 dB/octave asymptotic);
- stable, tuneable resonance and musical self-oscillation;
- less dramatic resonance-dependent bass loss than the current Analog ladder where matching listening references indicate;
- a different overdrive/saturation curve (rounded OTA behavior, not simply the V2 input saturator relabeled);
- Juno-style pre-filter HPF and bipolar filter envelope, which are separately audible;
- variant-specific cutoff/resonance calibrations, modest noise/tolerances.

No exact Roland/Arturia filter topology is proven by the user's asinhf observation. The goal is an original engineering model with verifiable four-pole signal behavior. Build the reliable linear core first, then introduce the nonlinear OTA model after tests.

### 5.2 Linear TPT core (mandatory first pass)

Existing Analog has gTable mapping from MIDI-style cutoff to the trapezoidal prewarp coefficient. Reuse it when the input sample rate and cutoff are the same. For a stage with integrator state s:

g = tan(π f_c / f_s),  G = g / (1 + g),  β = 1 / (1 + g)

y = G u + β s,  v = G (u − s),  s' = s + 2v = 2y − s.

Four stages are cascaded. With a global resonance feedback coefficient k, define:

S = β (G³ s₁ + G² s₂ + G s₃ + s₄)

y₄ = G⁴ (x − k y₄) + S  ⇒  y₄ = (G⁴ x + S) / (1 + k G⁴).

This is the linear ZDF feedback solution for the four cascaded integrators; it is stable when appropriately clamped and correctly updates the actual state sequence for the corresponding u=x-k*y4. Do not insert a nonlinear function after computing the linear closed-form feedback and call it an exact nonlinear solver. That would only be a deliberate approximation and needs separate validation.

Pseudo-interface:

```cpp
class OtaFilter {
public:
    void reset() noexcept;
    void prepare(double internalSampleRate) noexcept;
    float processLinear(float input,
                        float g,           // already prewarped
                        float resonanceK,
                        float compensation) noexcept;
    float processNonlinear(float input, float g, float resonanceK,
                           float drive, float dcBias,
                           float compensation) noexcept;
    bool isQuiet() const noexcept;
private:
    float s[4]{};  // states; all finite
    float yPrev[4]{}; // warm start for nonlinear solver
};
```

Cutoff mapping: retain existing analog.tone range and logarithmic mapping. The reference XML's extreme 0.2991–102600 Hz range is a mapping artifact and must not be fed into tan(pi*f/fs) beyond Nyquist. Clamp f to a safe cap, initially min(0.45 * internalRate, 40 kHz) as in V2, and clamp g against non-finite inputs. Exponential cutoff modulation stays in semitone space (existing implementation) before converting to g.

Resonance mapping: analog.resonance remains 0..100% with identical host ID. The OTA filter has an independent internal mapping k_OTA = curve(resonance, variant); default curve(0)=0 and self-oscillation occurs near the upper extreme (test in isolation). A first candidate is k_OTA = 4.0*resonance but do not assume the self-oscillation threshold without measuring with nonlinear drive, frequency warping and compensation. Allow control near 1.0 to reach sustained oscillation under appropriate conditions, with bounded level. Calibration data in code, not imported proprietary arrays.

### 5.3 Nonlinear OTA solver (required for high-fidelity release)

Use a numerically defensible implicit model with four nonlinear first-order stages. A useful original normalized saturating transconductance function is:

φ_d(z) = z when d ≈ 0;  φ_d(z) = tanh(d z) / d when d > 0.

It has unity small-signal slope, bounded large-signal response and a familiar OTA-like smooth transfer, but it is not an assertion of the exact physical IR3109 transistor equations. Tune stage gains/asymmetry only after tests. asinh may appear in an inverse current/voltage expression in some models; its presence in a binary says nothing about the final recurrence.

For trapezoidal integration with each stage's state s_i, solve the four unknown stage outputs y_i simultaneously:

F₁ = y₁ − s₁ − g φ_d(x − k y₄ − y₁) = 0

F_i = y_i − s_i − g φ_d(y_{i−1} − y_i) = 0,  i = 2, 3, 4.

The stage feedback is implicit. Using s'_i=2y_i-s_i after solving preserves the TPT state convention. The Jacobian has a sparse cyclic structure:
- J[0,0] = 1 + g*phi'(x - k*y4 - y1)
- J[0,3] = g*k*phi'(x - k*y4 - y1)
- J[i,i] = 1 + g*phi'(yPrevStage - yi), for i=1..3
- J[i,i-1] = -g*phi'(yPrevStage - yi), for i=1..3
- all other entries zero.

For phi=tanh(d*z)/d, phi'(z)=1-tanh(d*z)^2. Use the exact derivative of whichever approximation is actually used. A fast polynomial/tanh implementation whose derivative does not match can destabilize Newton iteration.

Bounded Newton procedure per sample (initial design):
1. Clamp input and coefficient ranges to documented safe bounds; read previous valid yPrev warm start.
2. Perform at most 4 Newton steps, solving a fixed 4×4 linear system on stack (or exploit the cyclic sparse structure); fixed-size arrays only.
3. Limit each step's magnitude and optionally perform at most 2 fixed damped line-search trials if residual grows. Never do an unbounded while-loop.
4. Accept convergence when max(|F_i|) is below a scaled epsilon; collect an atomic counter for diagnostics outside the audio thread.
5. If no convergence: use a guarded stable one-step/bounded fallback without copying a new unknown state. Log only a counter outside RT; mark any repeated fallback as a test failure. If high-frequency modulation causes frequent fallback, choose the stable linear OTA mode for that quality tier until solved.
6. Update state only after finite valid y values are found. Prevent runaway through bounded effective k, saturation and gain normalization; do not apply arbitrary per-sample clip(y4) to hide unstable state.

CPU caution: 16 voices × 4× oversampling × 4 stages × 4 Newton iterations is substantial. Run a benchmark against the linear OTA first. If the nonlinear solver exceeds the release budget, optimize solver math, reduce iterations with good warm starts, solve the cyclic Jacobian analytically, or implement nonlinear processing in a selected quality tier. Do not silently switch to cheap DSP while calling it the full model.

### 5.4 Unit-test invariant for the nonlinear solver

At drive=0 or with phi(z)=z, nonlinear-solver output must match processLinear() to floating-point tolerance for all valid g, k and states. This is the primary verification that the implicit math and state update are consistent. Test both impulse and steady sine response, with cutoff sweeps.

### 5.5 Drive, bias, makeup and resonance noise

The existing analog.filterDrive, analog.drive.bias, analog.drive.trim stay functional with the same musical meanings. In OTA mode:
- filterDrive: input drive gain, reused as an OTA saturation control, with a calibrated range; preserve the old curve in Ladder mode.
- drive.bias: small input asymmetry, DC compensated. Do not claim even harmonics from a perfectly symmetric tanh transfer alone.
- drive.trim: existing output trim, applied after the chosen filter.
- Bass/resonance compensation: an OTA-specific curve, measured to keep usable weight under resonance, without removing the possibility of self-oscillation.
- analog.filter.juno.resNoise: seeded very quiet noise injected in resonance feedback, not a fixed audible hiss. Default 0; can optionally raise above zero for character. Noise should not change filter cutoff calculation or exceed bounded amplitude.
- analog.analog: multiplies static per-voice cutoff/resonance mismatches; it must not inadvertently affect Classic+Ladder legacy patches.

The maximum resonance must self-oscillate with bounded amplitude and stable internal state; tests at frequencies from 50 Hz to near the safe Nyquist cap.

### 5.6 Filter wrapper and switching

A filter-model transition renders both valid paths, crossfades their outputs (with a correlation-aware or conservative level-matched law) over a bounded period, and then retires the old path. Do not route HPF solely through ota if a crossfade requires simultaneous input normalization: during fade, each path receives appropriate input according to its own mode. Keep crossfade routing consistent with the selected pre-VCF HPF.

The host output latency stays the same as the existing 4× path; the filter adds zero block latency. Never change reported latency on filter mode or HPF steps. Any gTable sharing must use the internal rate and be rebuilt only in prepare() on sample-rate change, not on realtime control edits.

## 6. JUNO HPF: 6/60/106 VARIANTS AND MODES

### 6.1 Location and implementation

The Juno HPF is a per-voice pre-VCF stage for OTA mode: DCO/selected source + shared noise → HPF → OTA LPF → VCA. It is not another resonant four-pole effect. Implement dsp/JunoHpf.h in pure C++ using stable first-order TPT highpass and an optional bass shelving response for the 106 lowest position.

Avoid applying HPF in Ladder mode by default; an explicit future HPF always active switch is possible, but for this expansion the HPF belongs to the selected Juno filter chain.

### 6.2 Difference between physical families and source hypotheses

Roland Juno-60 original manual: low HPF setting passes the DCO unchanged. Higher settings cut increasing low-frequency content.
Roland Juno-106 original manual: HPF 0 boosts low end; 1 is approximately flat; 2 and 3 cut bass increasingly.
Uploaded Arturia Jun-6 V notes: suggest switchable stepped 6/60 and continuous 106 emulation parameter behavior. Treat that as a feature of the analyzed software, not a constraint on authenticity of hardware.

Proposed default calibration table (all values starting points for listening/measurement, not hardware measurements):

| Variant | Step 0 | Step 1 | Step 2 | Step 3 |
|---|---|---|---|---|
| JUNO-6 | flat/bypass | HP ~70 Hz | HP ~300 Hz | HP ~1000 Hz |
| JUNO-60 | flat/bypass | HP ~70 Hz | HP ~300 Hz | HP ~1000 Hz |
| JUNO-106 | bass shelf +3 dB @ ~120 Hz | flat/bypass | HP ~250 Hz | HP ~1000 Hz |

Choose calibrated values by actually measuring/recording source hardware or reliable authorized references. If position 3 needs to reach ~2700 Hz to match the user-supplied Arturia mapping, expose a frequency-calibrated creative profile rather than asserting original Roland behavior.

Implementation:
- bypass path must output exactly input when flat/bypass (not a hidden 17 Hz highpass unless explicitly chosen);
- steps 1–3 run a stable one-pole 6 dB/oct filter (or variant-calibrated combination as measured);
- position 0 on 106 runs stable first-order low shelf; a simple gain ramp on bass is not equivalent to a shelf.
- step transitions use a 10–25 ms changeover; no clicks.
- host parameter is analog.filter.juno.hpfStep enum 0..3.
- if a future optional continuous HPF is desired, append another normalized parameter and choose a specific variant/creative mode. Never change the 4-choice enum range after publishing.

### 6.3 First-order TPT highpass equation

Given input x, stage state s, and cutoff g=tan(pi*fc/fs), G=g/(1+g), linear lowpass lp=G*x+(1-G)*s; output hp=x-lp; update s=2*lp-s. This yields a stable one-pole highpass under static coefficients and smoothed changes. Ensure DC rejection and no amplification at cutoff due to coefficient update mistakes. For 106 bass shelf, use a tested TPT shelving topology or juce::dsp::IIR equivalent in the integration layer only if it can be safely driven per voice without violating pure C++ layering; pure C++ is preferred.

## 7. ENVELOPES, LFO, FIXED ROUTES AND JUNO PERFORMANCE

### 7.1 Reuse existing ADSRs

Analog V2 has Voice::amp and Voice::env. Keep both. Add analog.juno.envelopeLink: when ON with OTA mode, VCA and filter read the same envelope law (the selected source envelope is the existing filter ADSR by default, with an optional link-choice if needed). This is not equivalent to copying envelope knob positions on every automation tick; link the runtime envelope signal. Allow the existing ADSRs to retain their stored settings for unlinked use.

VCA modes
- ENV (default): reuse current amplitude ADSR signal.
- GATE: sustain=1 while held/pedal-sustained, 0 on release; a fixed 1–3 ms de-click ramp on opening/closing. It is not a replacement for note-stealing ramp; existing steal fade still works.
- ENV2: optional creative mode only if clearly exposed; use the other ADSR, not an invented third ADSR. If added, never alter old amplitude envelope ID. For a focused first build use only ENV/GATE.

Transport/note ownership: Hold pedal keeps gate until pedal releases; note off with no pedal initiates the 1–3 ms ramp; all-sound-off kills safely. In mono legato, avoid re-opening gate if already held unless existing retrigger mode says otherwise.

### 7.2 Bipolar VCF envelope

analog.envDepth already ranges from negative to positive semitones and therefore already implements the required bipolar behavior. Retain it as the one source of truth. Optionally add an ENV polarity convenience switch only if it changes the sign in a non-destructive view layer; do not add another multiplying signed-depth parameter that makes modulation ambiguous. Easiest: show ENV knob in TONE popover with a signed range and an explicit + / - display.

Cutoff in semitone space, per voice:

```
cutoffNote = baseToneNote
           + keyTrack * (playedNote-60)
           + lfoAmount * lfoValue * depthSemitones
           + envDepthSemitones * envValue * velocityScaling
           + analogVoiceCutoffDispersion
           + PolyModCutoff, if assigned
```

Convert to Hz only after summing and clamp in internal-rate space. Negative env depth makes filter close/open in the opposite trajectory. Preserve current analog.tone, analog.keyTrack, analog.envDepth, analog.velocityToFilter, analog.lfo.cutoff and Poly Mod IDs/mappings.

### 7.3 Juno LFO DELAY and RISE

Do not duplicate OSP's LFO oscillator, waveform editor, sync, mod-wheel connection or modulation matrix. Add a per-voice depth envelope multiplying the existing LFO target depths when Juno mode behavior is enabled.

Initial range proposals: Delay 0–3.0 s, Rise 0–3.0 s, exponential knob mapping with exact 0 case. Reference notes report approximately 5 ms..3.08 s delay and 7 ms..2.89 s rise; we deliberately include 0 as a musically useful neutral state.

```cpp
float lfoEnvelope(uint64_t noteAgeSamples, double hostRate,
                  float delaySeconds, float riseSeconds) noexcept
{
    float t = float(double(noteAgeSamples)/hostRate);
    if (t < delaySeconds) return 0.f;
    if (riseSeconds <= 0.f) return 1.f;
    float u = std::clamp((t-delaySeconds)/riseSeconds, 0.f, 1.f);
    return u*u*(3.f-2.f*u); // smoothstep, no kink at start/end
}
```

- This is a depth envelope, not a new LFO; OSP LFO phase continues per current scope/free/retrigger rules.
- Note-on starts age at zero; mono legato either retains or restarts depending on existing articulation policy; document and test.
- Only apply this Juno depth envelope to the Juno oscillator's PWM/pitch modulation and to the global filter LFO when OTA/Juno behavior is selected. Avoid suppressing the non-Juno oscillator's existing LFO depth in a mixed patch unintentionally.
- For filter's LFO depth under mixed source models, use explicit analog.juno.filterLfoDelayEnabled, or only apply when Juno OTA selected. Defaults OFF to preserve existing patches.

### 7.4 PWM fixed source selection vs OSP modulation routes

In the JUNO DCO mode, PWMSource=manual/lfo/env is the musician-facing default; advanced modulation routes still work as additions if the synth genuinely reads them. Define sum order and limits: effectiveWidth = clamp(base + sourceDepth + existingPolyModIfSupported + voiceDispersion, 0.05,0.95). Existing analog.lfo.width1/2 should remain operative; do not silently ignore it for JUNO mode. For a Juno-faithful preset, zero unneeded generic width modulation routes.

### 7.5 Do not proliferate envelopes

The user notes Arturia has an additional Env2 for its extended mod matrix. Our Analog already has two distinct envelopes; the shared OSP modulation panel also has LFO/ENV routing constructs. Implementing a third/fourth ADSR for the sake of counting Arturia features adds CPU and UI clutter, and is out of scope. Add only the selectable signal routing needed to produce the Juno behavior.

## 8. SHARED BBD-STYLE JUNO CHORUS: ENGINE AND ROUTING

### 8.1 Why it is separate

The original Juno identity strongly depends on chorus, but chorus is a stereo bus effect, never an oscillator model. The existing Analog shared OSP effects (osp::PostProcessor) already include MOVEMENT/CHORUS, plus DRIVE/ECHO/SPACE. Do not replace or silently repurpose it. Implement an opt-in Juno-style chorus stage once per stereo bus, by default before existing post effects, with independent parameters. When both chorus types are enabled, render both because the musician explicitly chose them; optionally display a nonintrusive double-chorus indicator, but do not disable another parameter as a side effect.

The historical Juno-6/60/106 panels commonly provide OFF/I/II, not a true independent I+II switch on every unit. I+II exists in the supplied Arturia-style notes as an extra emulation/creative mode and should be labeled I+II (creative), not asserted as a hardware-accurate setting for all variants.

### 8.2 Processing stage

```
Existing 4× voice mix → 4×→1× decimator → existing post-voice stages
    → new junoChorus.processStereo(L,R,n) when enabled
    → existing OSP DRIVE/MOVEMENT/ECHO/SPACE effects
    → existing output DC block / guard
```

The exact post-effect insertion must be verified against existing Synth::render stage order and documented. Preserve the V2 output bit-identically when junoChorus.mode=OFF by a true bypass (no extra filtering, no delay compensation path).

### 8.3 Algorithm

A practical original BBD-inspired model is a modulated fractional delay with bandwidth shaping and optional clock-like noise. Avoid simulating thousands of discrete BBD stages; that is expensive and not proven necessary.

For each stereo channel, write prefiltered input to a preallocated ring buffer, then read a time-varying delay:

d_L(t) = d₀ + a·LFO(t),  d_R(t) = d₀ − a·LFO(t)

y_L = g_d x_L + g_w · LPF(delay(x_mid, d_L))

y_R = g_d x_R + g_w · LPF(delay(x_mid, d_R)).

For a stereo input, derive mid/side deliberately, not by always summing to mono. Choose a mono-compatible wet injection. Alternative pair of cross-coupled paths may sound better; test, do not claim historic exact schematic.

Initial character presets (design values, to calibrate by listening/reference; not claimed original hardware measurements):

| Mode | Modulation rate | Center delay | Depth | Wet | Intent |
|---|---|---|---|---|---|
| OFF | — | — | — | 0 | exact bypass |
| I | ~0.50 Hz | ~15 ms | ±2.0 ms | 0.32 | mild, airy width |
| II | ~0.80 Hz | ~18 ms | ±4.0 ms | 0.40 | deeper movement |
| I+II | mixed ~0.50/0.80 Hz | 14–18 ms | both pairs | 0.44 | creative, thick chorus |

Rates/depths are initial QA targets; refine under a matched-volume listening test with legitimately obtained hardware examples. In I+II, run a shared four-tap arrangement or two modulation paths inside one chorus processor, not a full duplicated postprocessor with twice the wet level. Design an optional mono/centered sum behavior if reference supports it.

### 8.4 Fractional delay and DSP hygiene

- JunoChorus::prepare(hostSampleRate,maxBlock) allocates ring buffers once; processStereo only processes samples/indices.
- Max ring length supports delay to at least 40 ms at highest supported sample rate + interpolation margin; memory bounded. Host sample rate must be re-prepared on change.
- Interpolate delay taps with cubic Hermite or third-order Lagrange; avoid nearest-neighbor zippering.
- LFO as band-limited triangle/sine with phase continuity; anti-aliased rounded triangle is reasonable. Smooth rate/depth changes over 20–50 ms; preserve phases when modes change.
- Wet path BBD coloration: simple band-limited passband (for initial tuning consider LPF 7–12 kHz + gentle highpass 70–200 Hz) and optional drive/pre-/de-emphasis. The band limits are creative starting values and need listening calibration.
- Optional analog.juno.chorus.noise: pink-ish/filtered deterministic noise at low level, default 0/off to avoid unwanted plugin hiss. If enabled, inject in the wet path and gate/fade with activity to avoid continuous noisefloor while stopped; do not use nondeterministic RNG.
- No negative delays or invalid ring reads when modulating or switching.
- Zero internal dropout on bypass and no output latency change (chorus is a time-varying delayed wet signal with direct dry, not an added plugin processing latency).
- When input is mono, provide sensible stereo widening while checking mono-sum phase cancellation; add a mono compatibility listening test.

### 8.5 Class skeleton

```cpp
class JunoChorus {
public:
    enum class Mode : uint8_t { off, I, II, IplusII };
    void prepare(double sampleRate, int maxBlock);
    void reset() noexcept;
    void setSettings(Mode, float wet, bool noise, float color) noexcept;
    void process(float* L, float* R, int samples) noexcept;
private:
    std::vector<float> ringL, ringR; // allocated in prepare only
    size_t writeIndex = 0;
    double phaseA = 0.0, phaseB = 0.0;
    // LPF / interpolation / smoothers / seeded noise states
};
```

If OSP already provides a better shared chorus building block, reuse its audio algorithm with an independent settings instance rather than duplicating code; do not route Juno CHORUS through the same MOVEMENT control instance.

## 15. AUTOMATED TEST MATRIX, SIGNAL MEASUREMENTS, CPU AND QA

### 15.1 Unit tests — exact assertions

DCO / oscillators
- Main DCO pitch with no FM: A4=440 Hz within 0.1 cent, sample rates 44.1/48/96/192 kHz, minimum and maximum current octave settings.
- Sub oscillator frequency = main / 2 within tolerance and correct alternating polarity over two complete main cycles.
- Saw/pulse switches produce their intended energy; turning both off removes fundamental source except any separately active sub/noise.
- Sub toggle and subLevel=0 both cause exact zero sub contribution, no DC bias.
- 50% pulse has near-zero DC; 20/80% duty cycle has expected harmonic nulls to numerical tolerance under static PW.
- Boundary PWM at 5/95% remains finite, no pathological bandwidth or unwanted silent pulses.
- PWM ENV and LFO differ perceptibly, follow correct per-note vs global scopes, and preserve smooth phase.
- Fast PWM at up to current LFO limits does not exceed prior B-spline alias-noise target by an unjustified amount; compare spectra against high-rate offline reference, not just naive saw.
- Oscillator2 hard sync still locks OSC1 to expected master frequency, including mixed OSC2=Juno mode; Poly Mod routes remain audible and do not alias more severely without explanation.
- Static dispersions are stable across repeated renders with identical seed/notes; different seed changes calibration, not overall pitch mean excessively.
- Juno-6 raw noise vs Juno-60 colored noise has a measurable distinct high-frequency spectrum at the same analog.noise level; Classic/Ladder legacy noise remains unchanged. Test DCO OSC2 low-frequency mode with SUB enabled to ensure no unintended infrasonic/DC output.
- Classic/Classic output under a V2 patch matches the baseline render. If a floating-point compiler or optimization change prevents bit identity, document RMS/correlation/maximum absolute difference and require listening sign-off; no unexpected sound changes.

OTA VCF
- Linear core DC gain and 24 dB/oct asymptotic response with low resonance; cutoff response tolerance e.g. ±1 dB of analytically expected simulation at measured frequencies below Nyquist after test setup compensation.
- Nonlinear model at drive≈0 equals linear solver for matched gain state (target RMS error < 1e-5 for normalized impulse/sine fixtures; tune floating-point tolerance to actual implementation).
- 25/50/75/95/100% res produces monotonic resonance behavior to the extent of design curve; verify self-oscillation only at deliberate upper settings, with bounded stationary amplitude.
- Modulation by ENV/LFO/KEY/POLYMOD works for both filter models, including negative envelope depths.
- Verify sweep/corner response and stability for abrupt coefficients, input ±8 (and extreme finite test), buffer sizes 1,7,64,512, varying sample rate and resonance.
- No NaN/Inf, loss of state, unbounded solver iterations or repeated fallback under normal operating range; solver-iteration max and fallback count exposed to tests.
- Filter-model switch during sustained note with noise/pulse/pad has bounded transient; target no spur/click exceeding a pre-agreed artifact threshold relative to surrounding signal (initial −60 dBFS impulse click metric under normal input; adjust if source itself transients strongly).
- No extra reported plugin PDC/latency; the existing 22 samples at 4× are verified on the same setup; no mode-dependent silent initial frames.

HPF
- Juno-6/60 step 0 is flat/bypass, not a residual highpass.
- Juno-106 step 0 low shelf increases low-frequency energy, step 1 flat, 2/3 increasingly attenuate lows.
- Highpass rejects DC with expected first-order slope; analog variant switching is click-free with stable state.
- HPF does not silently filter a Classic/Ladder-only preset.

Chorus
- Chorus OFF path is exact bypass and creates neither noise, phase delay nor a gain change.
- I/II have distinct measured modulation rates/depths and stereo width; I+II is distinct and bounded.
- Delay pointers always in allocated range at all tested sample rates and automation extremes.
- Noise OFF is exactly noise-free beyond source/previous processing; noise ON is seeded and level-bounded.
- Sum-to-mono of the chorus remains musically useful (no persistent destructive cancellation or near-silence), with an explicit mono compatibility score.
- Host block segmentation does not alter chorus phase/output for the same event stream.
- Turning chorus mode on/off under a pad makes no abrupt amplitude jump, and tail/smoothing behavior is documented.
